# 测试用例集

> 小红书「大家补充了」Skill — MVP 验收测试
> 版本：v1.2 | 日期：2026-05-30
> 总计：12 功能测试 + 7 多模态测试 + 8 语气测试 = 27 个测试用例

---

## 一、功能测试（TC）

### TC-01: 标准 explore 链接

**场景**：用户输入标准 explore 格式的小红书链接

**输入**：`https://www.xiaohongshu.com/explore/6a18efa20000000007010199`

**预期流程**：
1. Phase 0: 识别为格式 B → 直接使用
2. Phase 1: xhs CLI 成功认证 → read 返回数据 → comments 返回数据
3. Phase 1.5: 图片下载成功 → 多模态理解
4. Phase 2-3: 评论聚类 → 文案生成
5. Phase 4: 输出标准版文案

**预期输出**：包含 3-6 个区块的结构化总结文案

**验收标准**：US1 ✅

---

### TC-02: 短链解析

**场景**：用户输入 xhslink.com 短链接

**输入**：`http://xhslink.com/o/7m19VOgHvtj`

**预期流程**：
1. Phase 0: 识别为格式 A → WebFetch 跟踪重定向
2. 成功提取 note_id + xsec_token → 拼接 normalized_url
3. 后续同 TC-01

**预期输出**：与直接使用 discovery URL 效果一致

**验收标准**：US7 ✅

---

### TC-03: 分享链接

**场景**：用户输入含 source_type=share 的完整分享链接

**输入**：`https://www.xiaohongshu.com/discovery/item/6a18efa20000000007010199?xsec_token=xxx&source_type=share&app_id=xxx`

**预期流程**：
1. Phase 0: 识别为格式 C → 清理多余参数
2. 保留 note_id + xsec_token → 传给 xhs CLI

**验收标准**：正常读取并输出

---

### TC-04: 高赞热门笔记（5000+ 评论）

**场景**：评论量巨大的热门笔记

**输入**：任意 5000+ 评论的笔记链接

**预期行为**：
- 仅取首页 ~20 条主评论（MVP 策略）
- 输出中注明 `data_quality_note`: "仅分析了首页 N 条评论"
- 不使用 `--all`（避免超时）
- 处理总时长 < 60 秒

**验收标准**：正常完成，不超时

---

### TC-05: 冷门笔记（< 10 评论）

**场景**：评论区内容稀少的笔记

**输入**：评论 < 10 的笔记链接

**预期输出**：
- 友好提示："这篇评论区还比较冷清，目前大家的讨论还不多～"
- 如有有效评论仍做聚类分析
- `data_quality_note` 注明评论数量

---

### TC-06: 无效 URL

**场景**：用户输入非小红书链接或随机字符串

**输入**：`https://www.baidu.com` 或 `hello world`

**预期输出**："这个链接看起来不像小红书的链接哦～请确认是小红书笔记的分享链接或短链接"

---

### TC-07: 用户上传截图模式（降级）

**场景**：API 不可用时用户提供截图

**前置条件**：模拟 xhs CLI 未安装/未认证

**输入**：一张包含笔记正文和部分评论的截图

**预期流程**：
1. Phase 0: 无 URL → input_type=media
2. 进入 Phase 1Backup Level 1/2
3. Read 工具读取截图（多模态）
4. OCR 提取可见文字
5. Phase 2-3: 基于提取内容分析

**验收标准**：US9 ✅

---

### TC-08: 图片理解场景

**场景**：含图片的笔记（滤镜明显）

**输入**：美食/旅游/穿搭类笔记链接（配图 6+ 张）

**预期行为**：
- Phase 1.5 成功下载并理解所有图片
- Prompt 0 生成图片观察结果
- 如评论中有视觉关键词 → visual_signals 生成
- 输出中可能包含【关于图的讨论】区块

**验收标准**：US8 ✅

---

### TC-09: 图文争议场景

**场景**：评论中多条提到"P图""滤镜过重""实物不符"

**输入**：此类争议性笔记链接

**预期行为**：
- visual_dispute 聚类 present=true
- 校验信号 category=potential_contradiction
- 输出中**不做判定**，仅客观转述
- 使用安全句式："从图上看…但这也只是静态画面"

---

### TC-10: 视频笔记

**场景**：视频类型笔记（type=video）

**输入**：视频笔记链接

**预期行为**：
- image_list 可能为空或仅含封面
- 基于封面 + desc 文案分析
- 输出中注明"基于文案内容和封面图的分析"

---

### TC-11: Cookie 过期

**场景**：用户 Cookie 已过期（模拟）

**前置条件**：清除或修改 Cookie 使 status 返回 SessionExpiredError

**预期行为**：
1. Step 1.2 检测到未认证
2. 尝试 $XHS login（如配置允许）
3. 失败则输出友好登录指引
4. 不暴露技术细节

**验收标准**：US6 ✅

---

### TC-12: API 超时/网络异常

**场景**：网络不通时调用 API

**前置条件**：断网或模拟超时

**预期行为**：
1. API 调用超时（>15秒）
2. 重试 1 次
3. 仍失败 → 降级到 Phase 1Backup
4. 引导用户上传截图

**验收标准**：优雅降级，不报错崩溃

## 二、多模态专项测试（MT）

### MT-01: 美食笔记图片理解

**输入**：美食帖，滤镜明显（高饱和度/暖色调）

**检查项**：
- [ ] Prompt 0 识别出食物主体
- [ ] 描述了摆盘/色泽特征
- [ ] 注意到了色调/滤镜风格（不过度强调）
- [ ] 如有图中文字（菜单价签），被正确提取

### MT-02: 旅游笔记图片理解

**输入**：旅游帖，风景照为主

**检查项**：
- [ ] 识别场景类型（自然景观/城市/人文）
- [ ] 描述季节/天气/人流等环境要素
- [ ] 多张图的差异点被标注

### MT-03: 穿搭笔记图片理解

**输入**：OOTD/穿搭帖，效果对比评论

**检查项**：
- [ ] 只描述服装本身（颜色/款式/搭配）
- [ ] **绝对不评价身材外貌**
- [ ] 评论中的身材相关关切被中立转述

### MT-04: 图文矛盾型评论

**输入**：多篇"图和实物完全两码事"类型的评论

**检查项**：
- [ ] 归入 visual_dispute 或 different_exp
- [ ] **校验信号不做判定**
- [ ] 输出中使用不确定表达 + 限定语

### MT-05: 图片含文字（菜单/价签）

**输入**：图片中含有价格/菜单/说明文字

**检查项**：
- [ ] Prompt 0 的图中文字字段非空
- [ ] 提取的文字被纳入分析上下文
- [ ] 评论中提到的价格与图中价格能交叉参照

### MT-06: 纯自拍/人物照笔记

**输入**：图片主要是人物肖像

**检查项**：
- [ ] type 标记为 portrait
- [ ] 图片分析权重降低
- [ ] 聚焦于评论文字信息而非图片细节

### MT-07: 多图长笔记（12-18 张）

**输入**：图片数量 >= 12 张的笔记

**检查项**：
- [ ] 前 6 张详细理解
- [ ] 第 7-12 张概括理解
- [ ] 第 13+ 张标签级理解
- [ ] 总处理时间合理（< 60 秒）

## 三、语气测试（TT）

### TT-01: 无违禁词

**方法**：对完整输出运行禁用词扫描

**通过标准**：输出中不含以下任一词：风险识别、避坑指南、真假鉴别、事实证明、警告/警惕、骗/假/忽悠

### TT-02: 社区化表达

**通过标准**：输出中至少出现 2 个社区化词汇（薯友/大家/评论区/补充/提醒）

### TT-03: 保留不确定性

**通过标准**：输出中至少出现 2-3 个不确定性表达（看起来/好像/有网友提到/说法不太一致）

### TT-04: 非评判语气

**通过标准**：输出中无判定性表述（确实证明/肯定是/一定是）

### TT-05: 有谨慎小结

**通过标准**：结尾必须包含"建议大家结合自身情况参考，具体以实际情况为准哦～"

### TT-06: 图文表达规范

**条件**：涉及图片理解的输出

**通过标准**：
- 无"AI图像识别""经分析发现""图片证明"
- 有"从图上看""但这只是静态画面"类限定语

### TT-07: 视觉相关不判定

**条件**：visual_dispute 类别存在时的输出

**通过标准**：无"P了/没P""滤镜很重"作为自身判断（只作为评论转述）

### TT-08: 无 API 暴露

**通过标准**：输出中无以下术语：xhs/CLI/API/Cookie/json/命令行/Bash/curl/status/read/comments

## 四、端到端验收测试

### E2E-01: 完整 Happy Path

**步骤**：
1. 使用之前实测成功的真实笔记链接（含短链版本各测一次）
2. 完整走通 Phase 0→1→1.5→2→3→4
3. 检查输出质量

**通过标准**：
- [ ] US1-US10 全部满足
- [ ] 端到端耗时 < 90 秒
- [ ] 输出文案读起来像真人写的
- [ ] 无技术术语暴露
- [ ] 无违禁词
- [ ] 包含不确定性表达
- [ ] 结尾谨慎小结存在

### E2E-02: 降级 Happy Path

**步骤**：
1. 模拟 xhs CLI 不可用
2. 上传一张真实的小红书笔记截图
3. 走通降级路径
4. 检查输出质量

**通过标准**：
- [ ] 降级友好提示清晰
- [ ] 截图模式能产出有意义的结果
- [ ] 明确告知用户基于截图分析（信息可能不全）
