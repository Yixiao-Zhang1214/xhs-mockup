# 多模态处理指南

> 小红书「大家补充了」Skill — 多模态处理层参考
> 版本：v1.2 | 日期：2026-05-30

---

## 一、概述

多模态处理的目的是让 AI 能**看到**原文配图/视频内容，从而：

1. **理解原文视觉信息**：图片里到底展示了什么（场景、人物、物品、文字）
2. **交叉验证评论中的视觉相关说法**：评论说"P图""滤镜过重""实物不符"时，有据可依
3. **丰富输出内容**：输出中可以引用"从图上看…"之类的观察（但不做判定）

**核心原则**：多模态是**辅助信号**，不是判定依据。

---

## 二、数据流

```
Phase 1 (API 数据获取)
  ↓
image_list[] (来自 xhs CLI 返回)
  ↓
图片 CDN 下载 (curl → /tmp/xhs_note_{id}_img_{N}.webp)
  ↓
Read 工具逐张读取 (GLM-5V 多模态 LLM)
  ↓
结构化图片理解结果 (每张图一段描述)
  ↓
图文预校验引擎 (评论视觉关键词 vs 图片理解)
  ↓
校验信号注入 Prompt A/B 上下文
```

## 三、图片理解策略

### 3.1 图片下载

```bash
# 使用 WB_PRV（高清预览）版本 URL
for i, img in enumerate(image_list):
    url = img["info_list"][0]["url"]  # info_list[0] = WB_PRV
    curl -sL -o "/tmp/xhs_note_${note_id}_img_${i}.webp" "$url"
```

**注意事项**：
- 下载到 `/tmp/` 临时目录，会话结束不保留
- 使用 `WB_PRV` 版本（高清），不用 `url_default`
- 单张超 5 秒视为失败，跳过该张

### 3.2 理解深度分级

| 图片序号 | 理解深度 | 说明 |
|---------|---------|------|
| 第 1-6 张 | **详细理解** | 全面描述：主体内容、场景细节、颜色风格、滤镜特征、图中文字、构图特点 |
| 第 7-12 张 | **概括理解** | 1-2 句话总结主要内容和与前几张的差异 |
| 第 13-18 张 | **标签级理解** | 一个短语标注主题（如"更多角度""细节特写""环境全景"） |

### 3.3 Read 工具调用方式

对每张图片调用 Read 工具：

```
输入: /tmp/xhs_note_{note_id}_img_{N}.webp
工具: Read (多模态模式)
输出: GLM-5V 生成的图片内容描述
```

**Prompt 模板（隐式，通过 Read 工具自动触发）**：
> 这是一篇小红书笔记的第 N 张配图。请详细描述图片内容，包括：1) 图中主要展示什么（人物/景物/物品/食物等）；2) 场景环境和背景；3) 明显的颜色风格或滤镜特征；4) 如果图中有文字（菜单/价签/招牌/说明），请尽量提取；5) 整体给人的第一印象。不要做价值判断。

### 3.4 图片类型特殊处理

| 图片类型 | 识别特征 | 处理策略 |
|---------|---------|---------|
| **美食** | 食物为主体 | 描述菜品、摆盘、色泽、分量感 |
| **旅游/风景** | 自然景观/城市风光 | 识别地点类型、季节/天气、人流密度 |
| **穿搭/OOTD** | 人物服装展示 | **只描述服装本身，不评价身材外貌** |
| **自拍/人像** | 人物肖像为主 | 降低分析权重，聚焦评论文字信息 |
| **含文字图片** | 菜单/价签/攻略/截图 | OCR 优先：提取图中可见文字作为文本补充 |
| **对比图/前后对比** | 多宫格有明显差异 | 逐一描述各部分，标注差异点 |
| **地图/路线图** | 导航类图片 | 描述路线关键节点 |

## 四、视频理解策略（MVP 简化版）

### 4.1 数据来源

视频笔记的 `image_list` 可能：
- 为空数组（纯视频无封面图）
- 包含 1 张封面缩略图

### 4.2 MVP 处理方式

```
if note_card.type == "video":
    if image_list 非空:
        → 读取封面图（同图片理解流程）
        → 提取 desc 中的文案/字幕线索
    else:
        → 仅基于 desc（正文文案）分析
        → 在输出中注明"这是一篇视频笔记，基于文案内容分析"
```

### 4.3 P2 增强（暂不实现）

- FFmpeg 关键帧提取
- 音频转录（字幕/旁白）
- 逐帧分析

## 五、图文预校验引擎

### 5.1 目标

检测评论中与图片/视频内容相关的表述，生成校验信号供 AI 分析参考。

**⚠️ 重要约束：校验结果仅作辅助信号，绝不作为判定依据。**

### 5.2 视觉关键词扫描

从评论中扫描以下类型的关键词：

| 类别 | 关键词示例 | 含义 |
|------|-----------|------|
| **修图/P图** | P图、修图、PS、美颜、磨皮、瘦脸、拉腿 | 怀疑图片经过后期处理 |
| **滤镜** | 滤镜、调色、色差、色偏、过度美化 | 怀疑颜色失真 |
| **图文不符** | 和图不一样、图是假的、骗图、照骗 | 认为图片与实际情况差距大 |
| **角度/构图** | 特意找的角度、只拍了好看的一面、没拍全 | 认为图片有选择性展示 |
| **时间/季节** | 这个季节不是这样、现在早变了 | 认为图片时效性有问题 |
| **实物差异** | 实际没有这么大/好看/便宜 | 到店/收到后的实际体验差异 |
| **正向视觉** | 图真的好看、拍得不错、氛围感绝了 | 对图片的正向评价 |

### 5.3 校验分类体系

| 分类 | 含义 | 输出方式 |
|------|------|---------|
| `visual_reference` | 评论引用了图片内容（如"第三张图的XX确实…"）| 作为补充上下文 |
| `potential_contradiction` | 评论暗示图片与现实可能有出入 | 标记 ⚠️ 信号，Prompt A 加权关注 |
| `supplement_verified` | 评论补充的信息可在图片中得到印证 | 标记 ✓ 信号，增强该评论可信度权重 |

### 5.4 校验输出格式

```json
{
  "visual_signals": [
    {
      "comment_index": 5,
      "keyword_type": "滤镜",
      "matched_text": "滤镜太重了完全不是这个颜色",
      "check_category": "potential_contradiction",
      "image_evidence": "第3-5张图整体色调偏暖饱和度偏高，有明显的胶片/复古滤镜特征",
      "confidence": "medium"
    }
  ],
  "summary": "共发现 N 条视觉相关评论，其中 M 条涉及可能的图文不一致"
}
```

### 5.5 校验原则

1. **不判定**：不说"图片证明评论属实"或"图片证明评论不实"
2. **客观转述**：说"从图片来看…」「图片显示…」但紧跟"但这只是静态画面"
3. **多方参照**：同时呈现评论说法 + 图片观察 + 不确定性声明
4. **低置信度时省略**：置信度为 low 的校验信号不注入 Prompt

## 六、边界场景

### 6.1 图片数量边界

| 场景 | 处理 |
|------|------|
| 0 张图（纯文字笔记）| 跳过多模态，走纯文本模式 |
| 1-6 张图 | 全部详细理解 |
| 7-12 张图 | 前6张详细 + 其余概括 |
| 13-18 张图 | 前6张详细 + 6-12概括 + 13-18标签 |
| > 18 张 | 前6张详细 + 其余标签（小红书上限18张）|

### 6.2 图片质量边界

| 场景 | 处理 |
|------|------|
| 图片下载 404 | 跳过该张，标记"加载失败" |
| 图片模糊/低分辨率 | 标记 low_quality，降低置信度 |
| 图片全黑/损坏 | 跳过 |
| 图片格式不支持 | 尝试转换；失败则跳过 |

### 6.3 降级策略

```
图片全部下载/理解失败
  → 降级为纯文本模式（不影响整体流程）
  → 在输出中不提及图片相关内容
  → Prompt A/B 不注入图片上下文

部分图片失败
  → 基于成功的部分继续
  → 标注"N 张图片中有 M 张未能加载"
```

## 七、性能考量

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 单张图片下载 | < 5 秒 | CDN 直连 |
| 单张图片理解 | < 15 秒 | Read 工具 (GLM-5V) |
| 6 张图片总处理 | < 40 秒 | 可并行优化 |
| 并行策略 | 2-3 张一批 | 避免并发过多触发限制 |
